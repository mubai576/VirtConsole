## 二、单元测试

- **qmp-engine（7）**：PPM 帧解析、QMP 命令（Mock 传输层）、文本→QKeyCode 映射、错误传播
- **vc-ui（42）**：
  - `pve.rs`：实体列表解析（宿主优先 + CPU% 换算）、三模判定、VM 详情、快照解析、
    宿主/VM RRD 解析、动作与快照 CRUD、连接失败处理
  - `config.rs`：默认配置 round-trip、缺失文件回退默认值
  - `capture/keymap.rs`：XT set1 scancode 映射（钉住 ArrowUp=72 / Home=0x47 / F11=87 等具体值）
  - `capture/frame.rs`：脏区包围盒合并

**`keymap` 与 `frame` 的单测不挂 `cfg(unix)`**——挂上等于在 Windows 开发机永远测不到。
提交 `f173f50` 的方向键 bug 与 `merge_rect` 包围盒 bug 都是这么漏掉的。理由见 [20](20-架构总览.md) §二。

pve 测试用 `mock://` 后端，纯 Rust 离线可跑。**Mock 忠实复刻真实 PVE 行为**
（裸 `/qemu/{vmid}` 返回子目录列表、`memory` 为字符串），这是防回归的关键。

## 三、E2E 原理

`VIRTCONSOLE_TEST=1` 启动时：

1. `setup` 阶段启动 **120s 看门狗**（无报告则以退出码 2 终止，防挂起）
2. 前端 boot 检测 `test_mode` 命令为真 → 加载测试驱动
3. 驱动跑选定套件，每场景收集 `{name, pass, detail}`
4. 经 `test_report` IPC 上报 → Rust 打印 `[TEST]` 摘要 → `process::exit(0/1)`

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部通过 |
| 1 | 存在失败场景 |
| 2 | 看门狗超时（驱动未加载或挂起） |

### 核心不变量（`framework.js` 的 `assertSingleFocus`）

**每个测试步骤结束后强制校验**：

- 全屏最多 1 个 `.focused`
- 最多 1 个 `#tabbar .tab.focus`
- 最多 1 个 `.tab-view.active`
- 交互后无未捕获 JS 异常（`window.onerror` 捕获）

这条针对「双高亮 / 焦点顺序异常」这类系统性缺陷做自动回归，是整套测试的骨架。

### 驱动要点

- 键盘事件发给 `document.activeElement`（这样能进模态的 capture 监听并正常冒泡）
- 点击目标行触发 action 定位内部焦点（消除对内部 `focusIndex` 持久状态的依赖）
- `keyup(k, opts)` 支持 `opts`，要发 `{ code }` 才能验输入转发链
- `hover()` 需派发**冒泡的 `mouseover`**——React 的 `onMouseEnter` 由根节点委托合成，
  只发不冒泡的 `mouseenter` 触发不到

## 四、运行

# 只回归指定套件（逗号分隔）

### 输入套件（L7）验什么

它验的正是从前没人能发现的那段：

1. 命令是否**两平台都注册**（此前 `cfg(unix)` 让非 unix 拿到「命令不存在」而非输入层错误）
2. 按键是否真的走到 IPC
3. 可打印字符走文本通道**且不重复走按键通道**
4. 退出沉浸层是否补发抬起
5. `Ctrl+Alt+Q` 不转发给 VM

插桩 `window.__vcInputLog()` 记录最近 64 次下发。

**2026-08-17 改动（§7 记录）：L7 曾 6/6 全绿而 guest 一个键都没收到。**

两个原因叠起来：入口点是首页第一个快捷块，而 `Home.jsx:43` 进的是 `enter(9000)`
且**不带** `capture:true`，于是 `capture_start` 从不执行、`input_bus` 为空、
`dbus_ready()` 为假 → 回退 QMP → QMP 未连 → 报错；而原断言只要求
「`ok===true` **或** 留下非空 `err`」，后端报错也算通过。

- `L7_key_reaches_ipc`：`capture_input_ready()` 为真时收紧为**必须 `ok===true`**；
  未就绪（Windows 开发机、未连 VM）仍只要求留痕，保持本套件跨平台可跑。
- 新增 `L7_dbus_key_delivered_when_capture_on`：主动 `capture_start` 走真实 D-Bus 路径，
  只在 `capture_input_ready()` 真为 true 时做强断言；非 unix `capture_start` 未注册，
  catch 后跳过。E2E 数：Windows 80→81，真机 85→86。
- **状态编进步骤名**（`[started=…,status=…,ready=…]`）：`framework.step` 在 PASS 时把
  `detail` 写成 `""`，assert 文案会丢。只看 PASS 分不清「真的送达」与「未就绪跳过」——
  那正是误绿的形状。前端 `console.log` 不进 stdout（`[TEST]` 行走 Rust 侧 `test_report`），
  所以想让状态可见，只能编进 `name`。

**观测手段的坑**：验采集/输入不要用 `qm monitor screendump`。在 `vga: virtio` +
`-display dbus` 下它返回 QEMU 最后一次已知的 scanout 表面，没有 listener 挂着时是
**陈旧**的（实测同一 md5 隔 21 分钟不变，而 guest 在执行）。要用 vc-ui 自己的
listener 当观测点。详见 [90-历史记录.md](90-历史记录.md)。

## 七、测试契约（改前端时必须遵守）

|---|---|

> 已知坑（2026-09-21 记）：`window.__vcDebug` 有双形状——`Vm.jsx` 置为函数（`__vcDebug().termActive`），`useFrameStream.js` 的每秒统计将其覆盖为对象（含 `frameReceived/framePainted`）。测试态下因无真实 `vm-frame` 流未爆发；改任一处前先统一形状，不可静默加第三种。

## 八、测试暴露并修复的真实 bug

留档用，说明这套测试在防什么：

1. **`mock://` 被破坏**：`PveClient::new` 的 `trim_end_matches('/')` 把 `"mock://"` 变成 `"mock:/"`，
   `is_mock()` 恒 false → Mock 模式静默走真实 HTTP
2. **VM 配置端点错误**：用了裸 `/qemu/{vmid}`（返回子目录列表），应为 `/config` → 真机 VM 详情全空
3. **`memory` 是字符串**：`"2048"` 用 `as_u64()` 返回 0
4. **Tab 切换残留高亮**：`activate()` 只调 `unmount` 不调 `blur`，旧 Tab `.focused` 残留
5. **模态打开残留底层高亮**：打开前未清除内容区 `.focused`
6. **`DirtyState::merge_rect` 包围盒错误**：取旧矩形**左**边界（`rx.max(x+w)`），
   新脏区落在左上方时右下边界被截 → 画面残留旧像素。改为 `(rx + rw).max(x + w)`。
   **原 616 行单文件里没有任何测试能碰到这段**

## 九、边界

- QMP 控制台采集依赖 Unix socket + 运行中的 VM，未纳入 E2E（真机手工验证）
- 破坏性动作仅在 Mock 后端执行
- 每阶段结束跑一次全量套件，避免问题堆积
