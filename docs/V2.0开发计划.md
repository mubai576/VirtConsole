# V2.0 开发计划：基于 dbus-display 像素事件路径的画面采集

- 状态：**待排期**（M2.5 spike 已验证技术路线，2026-08-09）
- 目标：让虚拟机画面以流畅帧率（目标 60fps，实测基线 85fps@720x400）进入 Tauri 前端
- 依据：PRD V1.1 §6.2 / M2.5 spike 结论（见 [里程碑2.5](里程碑2.5-V2.0前置技术验证计划.md) §五）

---

## 一、技术路线决策（来自 M2.5 spike 结论）

| 方案 | 状态 | 说明 |
|---|---|---|
| **A：Scanout/Update 像素事件（gl=off）** | ✅ 已验证可用 | QEMU 每帧全量/局部像素经 D-Bus 直达 Rust，实测 **85fps**；与 V1.0 模式 1 数据形态一致，前端可复用 |
| B：linear DMABUF EGL 导入 | ⚠️ 待评估 | NVIDIA 私有 modifier 不可外部导入（external_ok=no）；需让 virgl 输出 linear，作为性能增强备选 |
| C：ScanoutDMABUF（gl=on） | ❌ 真机不可行 | NVIDIA tiled modifier 外部进程无法 EGL 导入 |
| D：Looking-Glass/IVSHMEM | 远期（V3.0） | 不受此限制，走共享内存 |

**V2.0 起步采用方案 A**：gl=off + Scanout/Update 像素事件。优点：
- 已验证（真机 85fps）
- 数据形态（RGB 像素 → Canvas）与模式 1 完全一致，前端渲染层零改动
- 无 GPU 私有格式依赖，NVIDIA/AMD/Intel 通用

## 二、架构设计

### 2.1 新模块 `ui/src/capture.rs`（dbus-display 采集）

与现有 `qmp.rs` 平行，不冲突。职责：

- 连接 D-Bus（session bus 或 `--bus-addr`），发现 `/org/qemu/Display1/VM` + Console
- 注册 Listener（复用 spike-dbus 验证过的逻辑：socketpair + RegisterListener + p2p zbus）
- 接收 `Scanout`/`Update` 事件 → 组装帧 → 复用 `vm-frame` 事件推给前端
- 与 QMP 输入链路共存：输入继续走 QMP `send_key`（已验证可靠），采集走 dbus-display

### 2.2 与现有系统的关系

```
虚拟机 (virtio-gpu)
   ├── QMP socket ──→ qmp.rs：输入(key/text) + 状态（保持不变）
   └── D-Bus display ──→ capture.rs：Scanout/Update 像素流 → vm-frame → 前端 Canvas
```

- **输入**：仍走 QMP（模式 1 已验证的输入通道），不改动
- **采集**：新增 capture.rs，复用 `vm-frame` 事件（前端 monitor.js 无需改）
- **配置**：`capture_mode` 字段（"qmp" 模式 1 / "dbus" 模式 2），默认可切换

### 2.3 PVE VM 接入

VM 需在启动参数注入 `-display dbus`（替换默认 VNC）。两种方式：
- **用户手动配置**：VM config 加 `args: -display dbus`
- **后续自动化**：vc-ui 提供"启用 dbus 采集"操作，自动写 args（需 VM 停机）

### 2.4 会话生命周期

- `vm_connect` 成功连 QMP 后 → 自动尝试连 D-Bus 采集（失败回退 QMP screendump）
- `vm_disconnect` → 关闭 D-Bus 连接与采集任务
- VM 停机 → D-Bus 对象消失 → 采集自动停止并提示

## 三、开发任务清单

1. **capture.rs 基础**：D-Bus 连接 + VM/Console 发现 + Listener 注册（复用 spike-dbus 已验证逻辑）
2. **帧推流**：Scanout 全帧 / Update 局部更新 → `vm-frame` 事件（RGB→base64，复用现有前端）
3. **配置**：`config.rs` 加 `capture_mode: String`（qmp/dbus），默认 dbus（若可用）
4. **集成**：`lib.rs` 注册 capture 状态与命令；`vm_connect` 联动
5. **前端**：monitor.js 增加 `dbus` 帧源处理（若需差异化）；状态栏显示模式
6. **P2 三模徽标**：VM 详情按显卡配置显示"模式 1/模式 2"，模式 2 可实际操作
7. **测试**：`VIRTCONSOLE_TEST` 测试模式下 dbus 采集走 mock（session bus 不可用时）
8. **真机验证**：PVE 真机，VM 9100 加 `-display dbus`，确认画面进前端 + 输入可用
