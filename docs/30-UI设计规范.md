## 一、设计目标

1. **十英尺 UI**：远距离可读、全程方向键可达、**零鼠标依赖**（鼠标可用但非必需）
2. **单一焦点**：任何时刻屏幕上只有一个高亮。Enter 确认、Esc 逐层返回、Home 回首页
3. **一致性**：全系统同一套组件语言
4. **沉浸模式**：控制台与终端全屏，隐藏 Tab 栏与顶栏，统一 `Ctrl+Alt+Q` 退出
5. **无 CDN**：第三方库（xterm.js 等）本地 vendor，kiosk 离线可用

> 约束：真机无桌面环境、kiosk 全屏；**设计基准 2K，一等目标 2K/4K**；方向键为主输入。

## 二、信息架构

顶栏常驻 Tab 条，全系统唯一一级导航：

```text
首页 · 虚拟机 · 浏览器 · 影视 · 设置
```

| Tab | 职责 |
|---|---|
| 首页 | 宿主状态总览 + VM 快速卡片 + 快捷入口 |
| 虚拟机 | **实体枢纽**：宿主机 + 各 VM 列表 → 实体页 |
| 浏览器 | 地址栏 + 快速链接 + 标签条 |
| 影视 | 固定影视站点入口（切入即在独立 Webview 窗口打开） |
| 设置 | 主题 / 缩放 / 采集 / PVE / 开机直连 / 系统信息 / 关于 |

**监控与终端不是一级 Tab**——它们天然「按实体」，下沉为虚拟机 Tab 内实体页的二级视图。

### 实体页二级导航（按实体差异）

| 实体 | 二级视图 |
|---|---|
| 宿主机 | 概览 / 监控 / 终端 |
| VM | 概览 / 监控 / 操作（另含控制台入口；V1.0 无终端视图） |

## 三、焦点与返回模型

```text
层次：Tab 内容区 → 实体列表 → 实体页 → 二级视图 → 控制台/对话框
状态：tab_focus(顶栏) ⇄ content_focus(当前 Tab 内部)
```

| 位置 | 按键行为 |
|---|---|
| Tab 栏焦点态 | ←→ 切 Tab；↓ 或 Enter 进内容区 |
| 内容区 | ←→↑↓ 组件间导航，Enter 确认 |
| 实体页二级导航 | ←→ 切二级视图；↓ 进内容，↑ 回导航 |
| 返回 | 二级视图 → 实体页 → 实体列表（Esc 逐级）；内容区 → Tab 栏（↑ 到顶或 Home） |
| 对话框 | Esc 取消，←→ 切按钮，Enter 确认 |
| **`Ctrl+Alt+Q`** | **所有沉浸模式的唯一退出键**（控制台 / 终端 / 浏览器） |

**Esc 的语义按场景不同**：普通态逐层返回；终端内交给 shell（不退出）；沉浸层内转发给 VM。

### 单高亮不变量

全屏最多 1 个 `.focused` + 最多 1 个 Tab 栏高亮 + 最多 1 个 active 视图。
测试每步后强制校验，见 [40-测试规范.md](40-测试规范.md)。

## 四、组件规范

| 组件 | 规范 |
|---|---|
| 卡片 Card | 表面色 + 1px 描边，圆角见 §五；聚焦时强调色描边 + 背景提亮 + `scale(1.015)` |
| 二级导航条 | 实体页顶部横向焦点条，当前项下划线 + 强调色 |
| 列表行 Row | 主标题 / 副描述 / 右侧徽标与迷你条；行高见 §五 |
| 状态徽标 | ● 运行中(绿) · ⚠ 已暂停(琥珀) · ○ 已停止(灰) · ◐ 启动中/关闭中(青) |
| 迷你条 / 曲线 | 纯 CSS 或 Canvas，**无图表库** |
| 确认对话框 | 标题 + 描述 + [取消][确认]，确认默认聚焦；危险操作（关机/回滚/强制停止）确认按钮红色 |
| 输入对话框 | 文本 / 密码 / 数字三种变体；Enter 提交，Esc 取消 |
| Toast | 仅提示信息，错误必须可见（kiosk 无 devtools） |
| 空态 | 无 VM / 未连接 PVE / 连接失败时给中文说明 + 重试或引导按钮 |

**模态约定**：打开时清除底层高亮，capture 阶段拦截按键不漏到底层视图，
Esc 只关模态不触发 Tab 导航。

## 五、视觉 token（miuix 移植）

miuix 是 Compose Multiplatform 的 Kotlin 库，**无 Web 实现**，故手写移植其设计语言。
token 取自 miuix 源码 `theme/Colors.kt`、`TextStyles.kt`、各 `*Defaults`。

### 5.1 配色

| 语义 | 亮色 | 暗色 |
|---|---|---|
| primary | `#3482FF` | `#277AF7` |
| primaryVariant | `#3482FF` | `#0073DD` |
| background | `#FFFFFF` | `#242424` |
| onBackground | `#000000` | `rgba(255,255,255,.9)` |
| onBackgroundVariant | `#8C93B0` | `#787E96` |
| surface | `#F7F7F7` | `#000000` |
| surfaceVariant / Container | — | `#242424` |
| surfaceContainerHigh | `#E8E8E8` | `#242424` |
| surfaceContainerHighest | `#E8E8E8` | `#2D2D2D` |
| outline | `#D9D9D9` | `#404040` |
| dividerLine | `#E0E0E0` | `#393939` |
| error | `#E94634` | `#F12522` |
| tertiaryContainer | `#EAF2FF` | — |
| windowDimming | `rgba(0,0,0,.3)` | `rgba(0,0,0,.6)` |

> 注意 miuix 暗色的 `surface` 是**纯黑**而 `background` 是 `#242424`，与常规「背景更暗、
> 卡片更亮」相反 —— 它的分组卡片用 `surfaceVariant #242424` 浮在黑底上。

**状态色**：运行绿 `#30d158` / 暂停琥珀 `#ffd60a` / 停止灰用 `onBackgroundVariant` / 危险红用 `error`。

### 5.2 miuix 原生排版与尺寸

`Title1 32 / Title2 24 / Title3 20 / Title4 18 / Main 17 / Body1 16 / Body2 14 /
Subtitle 14 Bold / Footnote1 13 / Footnote2 11`（sp），Paragraph lineHeight `1.2em`。

`Card.CornerRadius 16dp`、`Button{MinWidth 58, MinHeight 40, CornerRadius 16, padding 16/13}`、
`BasicComponent.heightIn(min=56dp) padding 16dp`、`SmallTitle.InsideMargin (28, 8)`、
`Switch 49×28 滑块 20 行程 4→25`。

### 5.3 本项目取值（2K 基准，1rem = 16px @2K）

相对 miuix 手机尺度放大约 **1.9×**（32/17），因方向键 + 远距离观看需要。

| 用途 | miuix 原生 | 2K 基准 | rem | 1080p / 4K 实际 |
|---|---|---|---|---|
| 正文 Main | 17sp | 32px | 2 | 24 / 48 |
| 摘要 Body2 | 14sp | 26px | 1.625 | 19.5 / 39 |
| 页标题 Title2 | 24sp | 44px | 2.75 | 33 / 66 |
| 分组标题 SmallTitle | 13sp | 26px | 1.625 | 19.5 / 39 |
| 列表行高 | 56dp | 112px | 7 | 84 / 168 |
| 卡片圆角 | 16dp | 28px | 1.75 | 21 / 42 |
| 页面边距 | 16dp | 64px | 4 | 48 / 96 |
| 卡片间距 | 12dp | 32px | 2 | 24 / 64 |

### 5.4 焦点态（miuix 没有，自建）

miuix 为触摸/鼠标设计，无键盘焦点模型。本项目定义：

- **焦点**：`0.1875rem`（3px@2K）`primary` 描边 + 背景提亮至 `surfaceContainerHighest` + `scale(1.015)`
- **按下**：沿用 miuix 的背景加深（与焦点态视觉可区分）
- **动效**：miuix 用弹簧物理参数（`response`/`damping`，非贝塞尔），
  CSS 用 `cubic-bezier(.32,.94,.6,1)` 250ms 近似

## 六、缩放模型（2K 基准 + 视口比例缩放）

十英尺场景下观看距离不变，同尺寸面板无论 1080p/2K/4K，元素都应占据**相同屏幕比例**，
即 px 需与视口宽度成正比：

```css
:root { font-size: calc(0.625vw * var(--vc-user-scale, 1)); }  /* 2560 → 16px */
```

全部 token 用 `rem`。实际根字号：**1080p → 12px、2K → 16px、4K → 24px**，三者物理尺寸一致。

已量化验证（行高 `7rem`）：

| 分辨率 | 1rem | 行高 | 正文 | 行高/视口宽 |
|---|---|---|---|---|
| 1080p | 12px | 84px | 24px | 4.375% |
| 2K | 16px | 112px | 32px | 4.375% |
| 4K | 24px | 168px | 48px | 4.375% |

三档占屏比例一致，即目标效果。

### 为什么废弃旧的固定 zoom 表

旧 `shared.js` 的 `SCALE_ZOOM` 把 4K 定为 `1.35`、2K 定为 `1.15`。
但 4K(3840) 相对 1080p(1920) 线性是 **2.0×**、2K(2560) 是 **1.33×**。
按旧表 4K 屏上 UI 只有应有物理尺寸的 67%（1.35/2.0）—— 4K 下行高
`56 × 1.35 = 75.6px`，仅占 1.969% 视口宽，比应有尺寸小 2.2 倍。
**这是「UI 效果不满意」可量化的主因。**

`--vc-user-scale` 供设置页做用户偏好（大字/紧凑），
`ui_scale` 配置项语义由「分辨率基准」改为「缩放倍率」，见 [20](20-架构总览.md) §五。

## 七、各 Tab 设计

### 7.1 首页

```text
┌────────────────────────────────────────────────────────────┐
│  宿主机状态   CPU ▓▓▓░░ 42%  内存 ▓▓▓▓░ 61%  磁盘 ▓▓░░ 55% │
│              GPU RTX 5070 Ti  利用 12% · 温度 51°C          │
├────────────────────────────────────────────────────────────┤
│  虚拟机                                   快捷              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐  [浏览器] [设置]   │
│  │ VM 9000  │ │ VM 100   │ │ VM 200   │                    │
│  │ ● 运行中 │ │ ⚠ 已暂停 │ │ ○ 已停止 │                    │
│  └──────────┘ └──────────┘ └──────────┘                    │
└────────────────────────────────────────────────────────────┘
```

- 数据源：`/nodes/{node}/status` + `/cluster/resources?type=vm`（3–5s 轮询）
- VM 卡片 Enter → **跨 Tab 深链**到该 VM 实体页
- 终端不放首页快捷（低频，入口在虚拟机 Tab → 宿主机实体页）
- 未连接 PVE：整块显示「未连接 PVE」+ [设置连接]

### 7.2 虚拟机（实体枢纽）

实体列表把**宿主机作为「实体 0」**，与 VM 同级：

```text
│ ▼ 实体列表                                              [刷新] │
│ │  宿主机   pve · PVE 9.2           ● 运行中  CPU 42% ▓▓▓░░ │
│ │  VM 9000 · Ubuntu 桌面   ● 运行中   CPU 5%  ▓▓░░  MEM 58%│
│ │  VM 100  · Windows 11    ○ 已停止   —                    │
```

实体页（以 VM 为例）：

```text
│ ◀ 返回   VM 9000 · Ubuntu 桌面       ● 运行中               │
│  概览 │ 监控 │ 操作                 ← 二级导航（←→ 切换）  │
├────────────────────────────────────────────────────────────┤
│  概览: 配置（CPU/内存/磁盘/显卡→采集模式）· 快照列表        │
│  监控: 实时指标 + 曲线                                      │
│  操作: [进入控制台] [关闭] [重启] [快照]                    │
```

**操作视图**（仅 VM）：

- **进入控制台**：沉浸模式，顶部角标显示采集模式，`Ctrl+Alt+Q` 退出
- **关闭**：优雅关机（PVE `shutdown`）+ 确认框；强制 `stop` 为红色危险项
- **快照**：创建弹命名对话框（自动填时间戳）；回滚 / 删除需两级确认
- 动作执行中：按钮禁用 + 徽标「◐ 启动中/关闭中」；失败 Toast 展示 PVE 错误
- **画面模式徽标**：按 VM 显卡配置显示模式 1/2/3，未实现的标注「待 V3.0」

### 7.3 监控（实体二级视图）

**宿主机指标**

| 指标 | 数据源 |
|---|---|
| CPU 总使用率 / 负载 / 每核 | `/nodes/{node}/status`、`/nodes/{node}/rrddata?timeframe=hour` |
| 内存 / 交换 | 同上 |
| 磁盘容量与 IO | `/nodes/{node}/disks`（容量）、`/rrddata`（IO） |
| 网络上下行 | `/nodes/{node}/rrddata` 或 `/network` |
| GPU 利用率/温度/显存/功耗 | `nvidia-smi --query-gpu=...` |

**VM 指标**（虚拟化层外部观测）

| 指标 | 数据源 |
|---|---|
| CPU 占用 % | `/nodes/{node}/qemu/{vmid}/status/current` |
| 内存（balloon/分配/已用） | 同上 + QMP `query-balloon` |
| 磁盘读写 | QMP `info blockstats` |
| 网络上下行 | QMP `info network` / PVE `netin` `netout` |
| 历史曲线 | `/nodes/{node}/qemu/{vmid}/rrddata?timeframe=hour` |

> 边界：VM 指标来自虚拟化层，**拿不到 VM 内进程级数据**。更细粒度需接
> qemu-guest-agent（当前不做）。

交互：←→ 切指标，指标卡高亮与曲线同步。曲线纯 Canvas 绘制，无数据显示「暂无数据」。
**实时刷新不得破坏焦点**——轮询回调必须完全派生自焦点状态，不能回灌高亮。

### 7.4 终端（宿主机 shell）

| 实体 | 支持 | 说明 |
|---|---|---|
| 宿主机 | ✅ | Rust PTY → `/bin/bash` |
| VM | ⛔ 待 V2.0+ | 复用 PVE serial console（`qm terminal`） |

- 前端 xterm.js（本地 vendor，无 CDN）
- 后端 Rust PTY，当前 root 单会话（后续降权）
- 进视图建会话，退出即销毁；崩溃自动重启并提示
- 退出用 `Ctrl+Alt+Q`；**Esc 交给终端自身**，方向键不干扰实体页导航
- 安全：仅本地回环监听

### 7.5 浏览器

- 地址栏（Enter 打开）+ 快速链接（PVE 后台 / 网关）+ 标签条
- 每标签 = 独立 Webview 窗口
- 标签条：←→ 选择、Enter 聚焦、Backspace 关闭
- `Ctrl+Alt+Q` 关闭全部标签并退出；Esc 回 Tab 栏（标签保留）
- 遗留：PVE 自签证书的 https 警告页处理

### 7.6 设置

| 设置项 | 取值 | 说明 |
|---|---|---|
| 主题 | 深色 / 浅色 / 跟随系统 | `<html data-theme>` 切 CSS 变量 |
| 界面缩放 | auto / 0.9 / 1.0 / 1.1 / 1.25 | `--vc-user-scale`，见 §六 |
| 画面采集 · 帧率 | 5 / 10 / 15 fps | 模式 1 轮询间隔 |
| 画面采集 · 缩放 | 原始 / 适配屏幕 / 自定义 | 信箱模式黑边 |
| PVE 连接 | 节点 + Token 或 用户名密码 | [测试连接] 校验 `GET /version` |
| 开机直连 | VMID 或关 | 非数字输入需校验拒绝 |
| 系统信息 | 只读 | 版本 / 平台 / 采集 / 连接 |

PVE 表单字段顺序：`host → node → method → token 或 用户名+密码`。
`method` 切换时 Token 与 用户名密码字段显隐互斥。必填校验失败时不关闭表单、跳回该字段。
