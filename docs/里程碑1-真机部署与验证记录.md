# 里程碑 1：HDMI 单应用渲染 —— 真机部署与验证记录

- 日期：2026-08-07
- 目标：在真实 PVE 宿主机上，通过 Weston Kiosk 将自研 Rust 应用渲染到 HDMI
- 结果：✅ 达成，已部署为开机自启服务

## 1. 真机环境

| 项目 | 实测值 |
| --- | --- |
| 系统 | Proxmox VE 9.2.0（Debian 13 / Trixie） |
| 内核 | 7.0.2-6-pve |
| GPU | NVIDIA GeForce RTX 5070 Ti（GB203，PCI 10de:2c05） |
| 驱动 | NVIDIA 开源内核模块 610.57.04（nvidia-open） |
| 内存 / 磁盘 | 46 GiB / 剩余 85 GiB |
| 显示器（EDID） | AVT GC553G2（HDMI 采集设备） |

> 注：PRD 原写 Debian 12，实测为 PVE 9 / Debian 13，已同步修正。

## 2. 软件栈

- Weston 14.0.2：DRM 后端 + kiosk-shell，以系统用户 `virtconsole` 经 seatd 运行
- 应用：winit 0.30 + softbuffer 0.4，全屏渲染测试图案（7 色条 + 移动白线）
- 部署：两个 systemd 服务（`virtconsole-weston` / `virtconsole`），开机自启
- 构建：Rust 1.97.1（rustup，minimal profile），release 二进制约 5.3 MB

## 3. 部署步骤（可复现）

### 3.1 基础环境

1. apt 安装：`weston wayland-protocols mesa-utils pciutils seatd build-essential pkg-config`
2. rustup 安装 Rust：`curl https://sh.rustup.rs | sh -s -- -y --profile minimal`
3. 源码同步至 `/root/virtconsole`，执行 `cargo build --release`

### 3.2 NVIDIA 驱动（重点）

1. 启用 Debian `non-free` 组件与 Proxmox `pve-no-subscription` 源
2. 添加 NVIDIA 官方 apt 源（CUDA repo，debian12 目录），安装 `nvidia-open`
3. 关键结论：
   - **Blackwell（RTX 50 系）必须使用 NVIDIA 开源内核模块**，闭源版拒载
     （`RmInitAdapter failed: requires use of the NVIDIA open kernel modules`）
   - 最终：`nvidia-open 610.57.04` 加载后 `/dev/dri` 出现 `card1` + `renderD128`，
     `HDMI-A-1` 连接器 connected
   - 驱动 550 无法编译到内核 7.0（`VMA_LOCK_OFFSET` API 变更）；610 可编译，
     但曾出现 gcc-14 偶发内部错误（IRA pass 段错误），重试 DKMS build 即通过
4. `/etc/modprobe.d/virtconsole-nvidia.conf`：

   ```text
   blacklist nouveau
   options nvidia-drm modeset=1
   ```

5. `update-initramfs -u` 后重启

### 3.3 服务部署

- `scripts/install.sh`：装依赖、创建 `virtconsole` 用户（video/render/input/tty 组）、
  启用 seatd、部署并启用两个 systemd 服务
- seatd 说明：Debian 的 seatd 默认以 `video` 组授权 `/run/seatd.sock`，无需额外建组

## 4. 部署过程中的坑与解法（归档）

| 问题 | 现象 | 解法 |
| --- | --- | --- |
| 内核 7.0 不支持旧驱动 | 550 DKMS 编译失败（VMA_LOCK_OFFSET） | 换 NVIDIA 官方源装 610 |
| Blackwell 拒载闭源驱动 | `RmInitAdapter failed` | 改用 `nvidia-open` |
| gcc-14 偶发 ICE | nvidia-uvm 编译段错误 | 重试 DKMS build |
| systemd `%U` 展开异常 | ExecStartPre 试图创建 `/run/user/0` 失败 | 改用 `RuntimeDirectory=virtconsole`（0700） |
| Weston socket 名漂移 | 出现 `wayland-1` 而非 `wayland-0` | 显式 `--socket=wayland-0` |
| 服务启动竞态 | 应用早于 Weston socket 就绪 | 应用服务加 ExecStartPre 等待 socket |
| 订阅源 401 | apt update 失败导致脚本中断 | install.sh 容忍（`|| true`） |
| NVIDIA 源签名被拒 | SHA1 绑定签名不符合新 apt 策略 | `trusted=yes`（官方 HTTPS 源，可接受） |

## 6. 遗留事项与风险

1. RTX 5070 Ti 为消费级卡，**不支持 SR-IOV**；PRD V3.0 的 SR-IOV 路线需更换硬件
2. 单 GPU：将来直通给虚拟机后宿主机将无 GPU，需加第二张卡
3. NVIDIA apt 源以 `trusted=yes` 绕过签名校验（官方 HTTPS 源，风险可控，可关注后续签名更新）
4. PVE 企业订阅源（pve-enterprise）每次 apt 更新报 401，无订阅时建议禁用
5. HDMI 物理画面需人工确认（当前 EDID 显示为采集卡，可从采集端查看）

## 8. QMP 引擎真机验证（2026-08-07）

- 创建测试 VM 9000（Debian 13 云镜像，virtio-gpu，3G 盘），QMP socket 位于
  `/var/run/qemu-server/9000.qmp`
- `qmp-engine` probe 实测：连接 + 握手 + `query-status` 正常，返回 `running`
- 关键发现 1：QMP 不接受 `"arguments": null`，无参数命令必须省略该字段
  （Mock 测试发现不了，真机验证才暴露，已修复）
- 关键发现 2：**PVE 的 QEMU 未编译 libpng**，`screendump` 的 PNG 格式不可用，
  仅支持 PPM（原始 RGB）。对模式 1 反而是简化：免 PNG 编解码，可直接喂给 Canvas
- screendump 帧率初测：720×400 文本模式 10 帧共 15ms，约 **1.5ms/帧（~660fps）**，
  1080p 按像素等比估算约 ~10ms/帧，PRD 的 10–15fps 目标可达
- 遗留：真实桌面分辨率（1920×1080）下的终标，需等办公场景虚拟机（带桌面环境）就绪

## 9. 模式 1（办公采集）接入验证（2026-08-07）

- `host` 新增 `display_source`：后台线程轮询 VM QMP screendump → PPM 解析 →
  共享帧 → 渲染循环读取并绘制（最近邻缩放 + 信箱模式）
- 环境变量 `VIRTCONSOLE_VMID=9000` 指定采集目标；未设置时回退测试图案
- 真机验证：应用连接 VM 9000 QMP 成功，`/dev/shm/vc-live.ppm` 正常产出
  （720×400 P6 PPM），无采集错误，HDMI 输出虚拟机实时画面
- 临时方案：应用服务以 root 运行（QMP socket 仅 root 可访问）；
  后续改为对 `/var/run/qemu-server` 加组 ACL，降回 `virtconsole` 用户
- 待办：VM 桌面分辨率下的画面适配（缩放已支持，等待带桌面的办公 VM）

## 10. QMP 键鼠投递实测（2026-08-07）

- 用 `input-demo` 在 VM 9000 上完成：输入用户名 → 密码 → 执行 `uname -a` →
  `echo VIRTCONSOLE_OK`，四步前后截屏均"画面变化: 是"，鼠标 abs/rel/btn 事件全部成功
- QMP `input-send-event` 的真实格式（经真机 + query-qmp-schema 确认）：
  - 参数为 `events` **数组**（可批量）
  - 键盘键值为 QAPI alternate：`{"type":"qcode","data":"a"}`（或 number）
  - 事件判别值：`key` / `abs` / `rel` / `btn`（按钮不是 "button"）
- 关键架构约束：**QEMU QMP monitor socket 同一时刻只允许一个客户端连接**，
  采集和输入必须共用同一条连接（后续 App 内做命令复用 / 队列，或独立代理）
- 已验证：QMP 输入对 virtio 显卡 / 无 uinput 场景完全适用（PRD 输入铁则成立）
