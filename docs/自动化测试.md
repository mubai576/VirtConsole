## 一、测试分层

| 层 | 内容 | 运行方式 | 依赖 |
|---|---|---|---|
| 单元测试 | qmp-engine 协议/PPM/键鼠映射；vc-ui 的 pve.rs JSON 解析、config.rs 读写 | `cargo test --workspace` | 无（走 `mock://` 后端 + 临时目录） |
| 全流程 E2E | 测试模式（`VIRTCONSOLE_TEST=1`）驱动真实应用跑 20 个场景 | 见下 | 需 GUI 会话（开发机/真机均可） |

## 二、单元测试

```
cargo test --workspace
```

- **qmp-engine（7 个）**：PPM 帧解析、QMP 命令（Mock 传输层）、文本→QKeyCode 映射、错误传播。
- **vc-ui（10 个）**：
  - `pve.rs`：实体列表解析（宿主优先 + CPU% 换算）、三模采集模式判定、VM 详情、快照解析、宿主/VM RRD 解析、VM 动作与快照 CRUD、连接失败处理。
  - `config.rs`：默认配置 round-trip、缺失文件回退默认值。
- pve 测试用 `mock://` 后端（`frontend` 无关，纯 Rust 离线可跑）。Mock 已忠实复刻真实 PVE 行为（裸 `/qemu/{vmid}` 返回子目录列表、`memory` 为字符串），可防回归。

## 三、全流程 E2E（测试模式）

### 原理

应用内置测试模式（`ui/src/testmode.rs`）：`VIRTCONSOLE_TEST=1` 启动时——

1. `setup` 阶段启动 120s 看门狗（无报告则以退出码 2 终止，防挂起）。
2. 前端 boot 检测 `test_mode` 命令为真 → 动态加载 `frontend/test/driver.js`。
3. 驱动跑 20 个场景，覆盖真实 IPC 与前端状态机，每场景收集 `{name, pass, detail}`。
4. 经 `test_report` IPC 上报 → Rust 打印 `[TEST]` 摘要 → `process::exit(0/1)`。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部通过 |
| 1 | 存在失败场景 |
| 2 | 看门狗超时（驱动未加载/挂起） |

### 场景清单（driver.js）

| 场景 | 覆盖 |
|---|---|
| tabs_render_4 / home_active | Tab 栏渲染、首页激活 |
| pve_connect / pve_entities / entities_host_first | PVE 连接、实体列表、宿主优先 |
| vm_detail | 真实 VM 配置解析（含采集模式） |
| destructive_actions | Mock 后端：VM 动作 + 快照 CRUD（真实后端自动跳过，避免改 VM 状态） |
| get_config / set_theme_persist | 配置读写 round-trip（结束后还原） |
| term_start / term_input / term_output_echo | 终端会话 + bash/powershell 回显断言 |
| esc_to_tabbar / enter_activates_vm_tab / home_key | 键盘导航状态机（Esc 回 Tab 栏、Enter 激活、Home 回首页） |
| entity_list_loaded / entity_page_subnav / monitor_cards / monitor_canvas / esc_back_to_list | 实体页导航：列表→详情→监控→返回 |

### 运行

**开发机（Windows，可连真实 PVE 或离线 Mock）：**

```bash
# 单元测试
cargo test --workspace

# 全流程 E2E（有真实 PVE 配置则连真实后端，否则 mock://）
VIRTCONSOLE_TEST=1 cargo run -p vc-ui
echo "exit=$?"
```

**真机（PVE 宿主，需要 Weston 会话环境）：**

```bash
systemctl stop virtconsole
XDG_RUNTIME_DIR=/run/virtconsole WAYLAND_DISPLAY=wayland-0 GDK_BACKEND=wayland \
  VIRTCONSOLE_TEST=1 /usr/local/bin/vc-ui
echo "exit=$?"
systemctl start virtconsole
```

> 说明：真机测试会短暂占用 HDMI 显示（测试完自动退出并恢复服务）。

## 四、测试暴露并修复的真实 bug

1. **`mock://` 被破坏**：`PveClient::new` 的 `trim_end_matches('/')` 把 `"mock://"` 尾部 `/` 去掉变成 `"mock:/"`，导致 `is_mock()` 恒 false，Mock 模式静默走真实 HTTP。已修复。
2. **VM 配置端点错误**：PVE 的 `GET /nodes/{node}/qemu/{vmid}` 返回**子目录列表**，真正的配置端点是 `/qemu/{vmid}/config`。旧代码用裸路径导致真机 VM 详情全空。已修复（mock 同步复刻真实行为防回归）。
3. **`memory` 字段为字符串**：PVE `/config` 里 `"memory": "2048"` 是字符串，`as_u64()` 返回 0。已改为兼容数字/字符串的 `as_u64` 解析。

## 五、说明与边界

- 前端为纯 JS（无 Node），未纳入单元测试框架；E2E 驱动直接操作真实前端 DOM + IPC，覆盖前端行为。
- QMP 控制台（VM 画面采集）依赖 Unix socket + 运行中的 VM，未纳入 E2E 场景（真机手工验证）。
- 破坏性动作（VM 启停、快照）仅在 Mock 后端执行，真实后端自动跳过。
