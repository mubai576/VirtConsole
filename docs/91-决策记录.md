## 采集与输入

| # | 决策 | 结论 | 理由 | 日期 | 状态 |
|---|---|---|---|---|---|
| D-10 | 输入通道 | **QMP `input-send-event` 为基准通道**，不依赖客体内 agent 或宿主 uinput | 对 virtio 显卡 / 无 agent / 安装界面全都适用，真机实测四步操作画面均变化 | 2026-08-07 | 有效 |
| D-11 | QMP 连接复用 | 采集与输入**共用同一条 QMP 连接**，`tokio::Mutex` 串行化 | QEMU QMP monitor socket 同一时刻**只允许一个客户端**，这是硬限制不是设计选择 | 2026-08-07 | 有效 |
| D-12 | 截图格式 | 模式 1 用 **PPM（原始 RGB）**，不用 PNG | PVE 自带的 QEMU **未编译 libpng**，PNG 不可用。反而是简化：免编解码，直喂 Canvas | 2026-08-07 | 有效 |
| D-13 | 不自编译 QEMU | 直接用 PVE 自带 QEMU 11 | `-display help` 已含 `dbus`，GL 库齐备。PRD 里「可能要自编译 QEMU」的前置风险消除 | 2026-08-09 | 有效 |
| D-14 | **放弃 `gl=on` 零拷贝** | 走 `gl=off` + `Scanout`/`Update` **像素事件** | NVIDIA 私有 modifier（`0x0300000000xxxxxx`）`external_ok=no`，外部进程 `eglCreateImageKHR` 返回 `EGL_BAD_MATCH`。像素路径实测 85fps 且与模式 1 数据形态一致，可复用前端渲染 | 2026-08-09 | 有效 |
| D-15 | 键盘 keycode | D-Bus `Keyboard.Press/Release` 用 **XT set1 scancode**，不是 Linux evdev keycode | 真机实测：按 evdev 填值时方向/功能/编辑键全错。已用单测钉住具体值 | 2026-08-09 | 有效 |
| D-16 | dbus 采集启用方式 | PVE VM 加 `args: -display dbus`，不改 PVE 配置模型 | 实测 QEMU 会**同时开 dbus-display 与默认 vnc，共存无冲突**，Web 控制台不受影响 | 2026-08-09 | 有效 |
| D-17 | 采集/输入回退位置 | 回退判断放在 **Rust `ui/src/input.rs`**，前端只发 `KeyboardEvent.code` | 前端 `if (e.code) ... else` 的 else 分支在 WebKitGTK 下**从来没执行过**（`e.code` 恒真）。平台差异属后端职责 | 2026-08-16 | 有效 |
| D-18 | 采集失败不阻断进层 | `capture_start` 失败仍进沉浸层，键盘走 QMP 回退 + toast | 没有像素流也能盲操作恢复系统，比直接不让进更有用 | 2026-08-16 | 有效 |
| D-19 | 模式 3（IVSHMEM） | **暂不启动** | 缺硬件：RTX 5070 Ti 是消费级卡不支持 SR-IOV，单 GPU 直通后宿主无显卡 | — | 有效 |

## 前端与架构

| # | 决策 | 结论 | 理由 | 日期 | 状态 |
|---|---|---|---|---|---|
| D-20 | 前端技术栈 | 纯 HTML/CSS/JS，无 Node 无构建 | V1.0 求最短链路，真机上不引入前端工具链 | 2026-08-07 | **已推翻 → D-21** |
| D-21 | 前端技术栈 | **Vite 7.3.6 + React 19.2.0** | 组件化后焦点状态可派生，手写 DOM 下「单高亮」靠人工维护不可持续 | 2026-08-16 | 有效 |
| D-22 | 新前端并存 | 建 `ui/web/`，**不覆盖 `ui/frontend/`** | 旧前端 P5 验收前保持可回退，`frontendDist` 改一行即可 | 2026-08-16 | 有效 |
| D-23 | vite 版本 | 固定 **7.3.6**，不用方案写的 7.1.12 | 7.1.x 有 5 条 dev-server 高危告警（路径穿越 / `server.fs.deny` 绕过 / WebSocket 任意文件读）；同 major 补丁升级后 0 漏洞 | 2026-08-16 | 有效 |
| D-24 | 缩放模型 | **2K 基准 + 视口比例**（`font-size: calc(0.625vw * var(--vc-user-scale))`），删掉 `documentElement.style.zoom` | 旧 `SCALE_ZOOM` 表在 4K 下给 1.35（需要 2.0），行高仅占视口宽 1.969% 而非 4.375%——**比应有尺寸小 2.2 倍，这是「UI 效果不满意」可量化的主因** | 2026-08-16 | 有效 |
| D-25 | 焦点实现 | 组件收 `focused` 属性渲染 `.vc-focused`，**不用 `:focus`**；DOM 焦点由 FocusProvider 托管 | 高亮成为纯派生状态，「单高亮不变量」断言才成立。例外：`TextField` 必须拿真实 DOM 焦点 | 2026-08-16 | 有效 |
| D-26 | 模态实现 | **保持命令式**（`lib/modal.js`），`Dialog.jsx` 暂不使用 | 调用点全是 `if (!await showConfirm(...)) return;` 线性流；套件 G/H 有 20+ 场景断言 `.modal`/`.form-row` 的 DOM 与 inline `display`。改 React 要给每个视图加状态机并重写断言 | 2026-08-16 | 有效 |
| D-27 | `onFocus` 派发 | **同步派发**，不用 `rAF` | 窗口未合成时 rAF 被节流甚至暂停，`onFocus` 迟到会让「切 Tab 后立刻按键」落在旧状态 | 2026-08-16 | 有效 |
| D-28 | Tab 状态 | `current`（光标）与 `activeId`（已激活）**分成两个 state** | 合成一个时 Tab 栏 ←→ 会挪动 `.active`，测试推算的按键次数全错 | 2026-08-16 | 有效 |
| D-29 | 命令分文件依据 | 按 **State 依赖**分，不按数量均分 | 一个文件对应一个 `manage` 进去的 State，改某个 State 只需看一个文件 | 2026-08-16 | 有效 |
| D-30 | UI 设计语言 | 手工移植 **miuix**（HyperOS Compose Multiplatform） | 它没有 Web 实现，只能照源码提取 token 与规格；换来一套已被大规模验证的十英尺观感 | 2026-08-16 | 有效 |

## 测试与工程

| # | 决策 | 结论 | 理由 | 日期 | 状态 |
|---|---|---|---|---|---|
