## 一、项目定位

在 Proxmox VE 宿主机上运行的**本地 HDMI 一体化终端系统**：无桌面会话、无容器、无第三方串流，
自研 Rust 应用直接独占 HDMI 输出，配极简手机遥控器（仅指令、不推流）。

- 运行环境：PVE 9.x / Debian 13（实测）
- 图形底座：Weston Wayland（KMS-DRM 原生，kiosk 全屏）
- 技术栈：Tauri 2 + Rust + QMP + D-Bus + Canvas + WebSocket
- 明确不用：Docker / X11 / GNOME / Moonlight / VNC / RDP / SPICE / uinput

### 终极目标

1. 抛弃闭源、冗余、不稳定的传统方案
2. 构建完全自研、分层适配全虚拟机场景的本地终端
3. 本地大屏一体化控制台 + 手机遥控器
4. **画面只本地渲染，手机只做指令控制**——零推流、无外网依赖

## 二、四大设计铁则

| # | 铁则 | 含义 |
|---|---|---|
| 1 | **开发与部署隔离** | UI / REST / 终端 / 遥控可在开发机 Mock 开发；三模采集与 QMP 输入必须真机验证 |
| 2 | **零系统输入模拟** | 彻底废弃 uinput，VM 键鼠统一走 QMP 或 D-Bus 原生投递 |
| 3 | **场景自适应三模渲染** | 按 VM 显卡配置选采集模式。**模式由 VM 配置决定，改模式需改配置并重启 VM，不可热切换** |
| 4 | **最小运行依赖** | 无桌面会话、无容器、无多余后台（WebKitGTK 等只是图形运行库） |

## 三、功能需求

### 3.1 PVE 虚拟机管理

- 基于官方 PVE REST API，不改底层配置文件
- VM 启停 / 重启 / 关机 / 快照 / 状态监控 / CPU 内存磁盘查看
- 多 VM 切换、资源占用实时展示
- 兼容 PVE 版本升级

### 3.2 宿主机网页终端

xterm.js 前端 + Rust PTY 直连宿主 Bash，完整支持快捷键、翻页、颜色、补全，替代本地 SSH。

### 3.3 内置浏览器

Tauri WebView 原生内核，**每个标签页 = 独立 Webview 窗口**（真隔离，不受 iframe 限制），
可开 PVE 后台与任意内网服务。

### 3.4 虚拟机画面渲染（核心能力）

三层采集体系，按 VM 显卡配置自动选择。技术细节见 [21-采集与输入.md](21-采集与输入.md)。

| 模式 | 适用 | 机制 | 帧率 |
|---|---|---|---|
| **1 QMP screendump** | 办公、Linux VM、控制台、低负载 | 轮询 screendump 取 PPM 原始 RGB，喂 Canvas | 10–15fps@1080p |
| **2 dbus-display** | 无直通、需流畅画面 | QEMU `-display dbus` 经 D-Bus 送像素事件到 Rust | 实测 85fps@720×400 |
| **3 IVSHMEM** | VFIO / SR-IOV 直通 | VM 内 Agent 抓帧（DXGI）写共享内存，宿主读取 | 原生 60fps |

模式 1 / 2 **无需 VM 内装任何程序**；模式 3 因硬件 IOMMU 隔离，宿主机读不到显存，必须 VM 内 Agent。

### 3.5 统一 VM 输入

全线废弃 uinput 与内核模拟 USB，统一走 QMP `input-send-event` 或 D-Bus Keyboard/Mouse 接口，
直接向 VM 投递键鼠事件。兼容 virtio 显卡 / 独显直通 / SR-IOV VF 全部场景。

### 3.6 手机遥控器（V1.0 未实现，设计保留）

**只控指令、不看画面、不推流、不解码。**

- 指令集：VM 启停/重启/快照、终端快捷指令、页面切换、系统状态查询、自定义快捷键
- 协议：局域网 WebSocket 私有协议 + Token 鉴权，默认端口 8899
- 特点：极低功耗、无视频编解码开销、不依赖外网

## 四、约束与已知限制

### 4.1 行业固有约束（不可解决）

1. **DXGI 桌面复制**：Windows 最小化 / 锁屏时黑屏（所有同类项目通病）
2. **SR-IOV 硬件隔离**：宿主机无法直接读显存，必须 VM 内 Agent
3. **virtio-gpu 无官方 Windows 3D 驱动**：virgl 仅 Linux 客户机可用。
   Windows 游戏 3D 需走模式 3 直通；Linux 客户机在部分 UEFI+3D 场景有兼容问题

### 4.2 主动舍弃（设计特性，非缺陷）

1. 不做手机视频流、不做远程桌面推流
2. 不用任何 VNC / RDP / SPICE
3. 不用 Docker 容器运行 GUI
4. 不用系统级输入模拟 uinput

### 4.3 硬件前置要求

| 需求 | 要求 |
|---|---|
| 模式 2 | 宿主机必须有 GPU（QEMU GL 渲染与 Weston 合成都要），建议独立于直通卡 |
| 模式 3 | 需支持 SR-IOV / vGPU 的显卡；**普通消费卡多数不支持** |
| QEMU | 需支持 `dbus-display`。PVE 9.x 自带 QEMU 11.0.0 已支持，无需自编译 |

## 六、部署体系要求

配套三套脚本保证环境一致、可复现、零手动配置：

| 脚本 | 职责 |
|---|---|
| `install.sh` | `install` 一键装依赖/配 Weston/配 systemd/权限/内核模块；`check` 环境自检；`remove` 无损卸载；`build` 构建前端+Rust |
| `check.sh` | 安装前自检（GPU、渲染节点、Weston、seatd、Wayland socket、内核模块） |
| `spike-qemu-check.sh` | QEMU dbus-display / OpenGL 能力检测 |

开机自启顺序：内核模块 → Weston → 等 Wayland socket 就绪 → vc-ui。
具体实现见 [50-部署运维.md](50-部署运维.md)。

## 七、音频

V1.0 / V2.0 不处理音频，留待 V3.0 统一追加 PulseAudio 重定向。

## 八、核心优势

1. 三模自适应采集架构，全场景覆盖
2. 摆脱 Moonlight / VNC / 容器 / 桌面环境的坑
3. UI / 运维 / 遥控可本地 Mock，开发效率高
4. 输入体系纯原生投递，无模拟失真、无权限坑
5. 手机遥控极简，无视频开销、无外网依赖
6. 全自研，无闭源绑定
